# UX-6 release-readiness audit

Baseline: master at `a087e37` (UX-5 merged). This audit separates software evidence from acceptance on the target kiosk. No physical EOS R50, webcam, printer, or Windows touchscreen was available for this audit. The application is **not production-qualified**.

## P0 — release blockers

* **Physical acceptance is UNVERIFIED.** The Canon EOS R50, JPEG/RAW+JPEG/RAW-only behavior, delayed transfer attribution, UVC switching, physical printer, paper dimensions, touchscreen, WebView2 and recovery after power loss require target hardware. `internal/camera/edsdk/reliability_test.go` uses a fake SDK and tests a late event within a configured grace period; it does not prove arbitrary delayed real-camera events cannot be attributed to a later shot. `--canon-validate` is an acceptance tool, not evidence that an R50 passed.
* **Ownership before startup was missing.** On the UX-5 baseline, `app.New` opened/migrated SQLite and ran recovery before Wails' single-instance enforcement; independent processes also had only process-local session mutexes. PR #39 added an OS-backed per-user application lock and per-library lock, including destination ownership during migration. PR #43 then made Documents resolution read-only until the lock is acquired. Lock files persist but contain no ownership state; the OS releases locks on process exit. Network filesystems and hostile/non-cooperating processes are not qualified. Cross-process contention and process-exit recovery are covered by CI run #312; target Windows filesystem and network-share behavior remain unqualified.
* **Trash recovery failures were not fatal.** Baseline startup logged `Store.Verify` failures and continued. This branch aborts before the UI/media server if recovery fails and releases ownership; an integration test covers a broken journal. No claim is made about durability under actual power loss. Basic same-volume hard-link support is now checked before starting new trash operations. Per-file permissions or nested mounts can still fail after work has started; the journal retains those operations for retry/recovery.

## P1 — must resolve or qualify before release

* Startup performs a synchronous integrity and orphan scan and recovered-video scan; it is safer than exposing unrecovered originals, but scales with media and directories. A synthetic local Linux test created 2,001 sessions and 10,005 media rows referencing small files; startup took about 0.16–0.19 seconds after fixture creation. This is not a Windows, network-share, HDD, antivirus, or cold-cache benchmark. Integrity verification contains best-effort filesystem and database operations; failure handling needs further review. Deferring work safely requires a separate recovery design.
* Shutdown closes capture, recording, camera/SDK, loopback server and SQLite. This branch waits for print polling and preferred-camera startup before releasing resources; physical disconnect, FFmpeg process lifetime, forced termination and repeated WebView2 lifecycle remain UNVERIFIED. Process locks are advisory and cannot protect a library against older application versions or external tools.
* The service rotates local logs at approximately 1 MiB with four backups and prunes older daily logs; the deliberate offline support ZIP is allowlisted and excludes raw logs, identity, paths and media. Privacy and recovery still need operator review on Windows.
* The app checks WebView2 before starting the window and provides recovery guidance; Windows CI runs headless startup/self-tests and exercises installer install/upgrade/uninstall. Actual WebView2 runtime deployment, offline installation and Wails window behavior on Windows 10/11 remain UNVERIFIED.
* English and Vietnamese resources, a persisted language setting, English fallback, translation tests and embedded Noto Sans fallback now exist. The translation catalog explicitly marks untranslated screens as English, so localization is partial; long-label layout in Vietnamese and rendered Vietnamese frame captions need target-screen review. Changing language does not rewrite saved compositions.
* Same-volume hard links are required for trash. Removable, redirected Documents, OneDrive, long/non-ASCII paths, read-only/low-space cases and network-backed folders need the actual filesystem matrix. A complete backup must include SQLite and media together while the application is shut down; SQLite alone is not a library backup.

## P2 — software evidence and outstanding qualification

* The standard CI build omits Canon DLLs. Trusted master CI stages a Canon-enabled executable for a one-day camera-free SDK compatibility smoke test only; it is not uploaded as a release artifact. Pull-request workflows do not receive the vault password. The applicable Canon redistribution agreement remains unreviewed, so public Canon-enabled distribution is blocked.
* CI run #274 is historical UX-5 evidence: Go/frontend tests, Windows portable tests, headless executable startup and file-port printing passed; its 157,386-byte PDF began `%PDF-`. This exercises native spooler/GDI against a software printer, not paper output. Current workflow also includes installer packaging, manifest/checksum checks and camera-free Canon initialization when secrets are available. Those checks cannot establish real device or display acceptance.
* Existing tests cover SQLite migrations, session recovery, cross-process lock contention and crash release, large synthetic libraries, trash/restore, frame composition, capture, video and print flows. The 2,001-session / 10,005-media fixture is a synthetic Linux profile, not a Windows startup benchmark. UVC uses synthetic inputs in automated tests. Screenshots are browser-harness captures, not WebView2 evidence. Consult `docs/UX5_AUDIT.md` and `docs/HARDWARE_TESTS.md` for earlier limits.
* CI records version/build metadata, executable and package checksums, unsigned status, and includes an Inno Setup per-user installer smoke test. These are qualification artifacts, not a signed or production release. Bit-for-bit reproducibility, a trusted signing identity, offline WebView2 installation, complete Vietnamese coverage, target filesystem behavior and physical acceptance remain open. A missing file-port driver is explicitly reported UNVERIFIED by CI and must not be treated as physical print PASS.

## Runtime ownership follow-up

PR #43 fixed the post-merge UX6-1 finding that Windows `ResolveLibrary` probed Documents writability before `app.New` acquired the library lock. Resolution is read-only; startup acquires ownership before layout creation or SQLite work, and falls back only after a non-contention access or initialization failure. A held library lock remains a hard startup error. CI run #312 passed the ownership, resolution, Windows package and startup tests. This does not qualify real Windows Documents, OneDrive, read-only volume, removable drive or network-share behavior.
