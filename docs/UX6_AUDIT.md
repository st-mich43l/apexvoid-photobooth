# UX-6 release-readiness audit

Audit state: UX-6 work through PR #48 on master (`5af10ac`, 2026-11-24). Historical UX-5 findings are retained where useful, with merged fixes identified below. This audit separates software evidence from acceptance on the target kiosk. No physical EOS R50, webcam, printer, or Windows touchscreen was available. The application is **not production-qualified**.

## P0 — release blockers

* **Physical acceptance is UNVERIFIED.** The Canon EOS R50, JPEG/RAW+JPEG/RAW-only behavior, delayed transfer attribution, UVC switching, physical printer, paper dimensions, touchscreen, WebView2 and recovery after power loss require target hardware. `internal/camera/edsdk/reliability_test.go` uses a fake SDK to test blocked retries after an unconfirmed transfer; it does not prove arbitrary delayed real-camera events cannot be attributed to a later shot. `--canon-validate` is an acceptance tool, not evidence that an R50 passed.
* **Historical artifact policy:** at the time of this audit, the standard artifact omitted Canon DLLs and a one-day staging artifact was used for camera-free validation. The single-file CI workflow supersedes that packaging: the trusted master artifact contains both the Canon SDK and FFmpeg.

## P1 — must resolve or qualify before release

* **Resolved in software, still needs Windows qualification: startup ownership and recovery.** PRs #39 and #43 acquire the OS-backed per-user and per-library locks before writes or mutable initialization; lock release after process exit is verified by cross-process CI. PR #45 makes incomplete media verification or interrupted-session recovery fatal before the UI/media server starts. The fixes have automated tests and Windows build/self-test coverage, but have not been validated against Windows OneDrive, network, removable or read-only filesystems, nor actual abrupt power loss.

* Startup performs synchronous essential recovery and a media/orphan scan; it is safer than exposing unrecovered originals, but its cost scales with media and directories. A synthetic local Linux test created 2,001 sessions and 10,005 media rows referencing small files; startup took about 0.16–0.19 seconds after fixture creation. This is not a Windows, network-share, HDD, antivirus, or cold-cache benchmark. PR #45 now propagates database and filesystem failures during recovery and aborts startup when integrity state cannot be established. Explicit deep verification still reads all checksummed photo originals synchronously and needs separate large-library timing on target storage.
* Shutdown closes capture, recording, camera/SDK, loopback server and SQLite. This branch waits for print polling and preferred-camera startup before releasing resources; physical disconnect, FFmpeg process lifetime, forced termination and repeated WebView2 lifecycle remain UNVERIFIED. Process locks are advisory and cannot protect a library against older application versions or external tools.
* The service rotates local logs at approximately 1 MiB with four backups and prunes older daily logs; the deliberate offline support ZIP is allowlisted and excludes raw logs, identity, paths and media. Privacy and recovery still need operator review on Windows.
* The app checks WebView2 before starting the window and provides recovery guidance; Windows CI runs headless startup/self-tests; historical runs also exercised installer install/upgrade/uninstall. Actual WebView2 runtime deployment, offline installation and Wails window behavior on Windows 10/11 remain UNVERIFIED.
* English and Vietnamese resources, a persisted language setting, English fallback, translation tests and embedded Noto Sans fallback now exist. PR #46 localized Studio navigation, Prepare Booth, Quick Settings, dashboard, diagnostics, photo/video setup, migration, and settings. PR #47 extended camera, printer, and Gallery workflows. PR #48 localized frame management and the Frame Builder toolbar/property panels. Remaining English can come from runtime camera/printer driver notes, frame validation warnings, category/frame data, and other device-supplied text. Vietnamese long-label layout and rendered Vietnamese frame captions still need target-screen verification. Changing language does not rewrite saved compositions.
* Same-volume hard links are required for trash. Removable, redirected Documents, OneDrive, long/non-ASCII paths, read-only/low-space cases and network-backed folders need the actual filesystem matrix. A complete backup must include SQLite and media together while the application is shut down; SQLite alone is not a library backup.

* Trusted master CI builds one portable executable containing the Canon SDK and FFmpeg and validates it on Windows. Pull-request workflows do not receive the vault password or publish the artifact.

This exercises native spooler/GDI against a software printer, not paper output. Those historical runs included installer packaging and checks; current CI delivers one executable, records its SHA-256 and performs camera-free Canon initialization on trusted master runs. Those checks cannot establish real device or display acceptance.
* Existing tests cover SQLite migrations, session recovery, cross-process lock contention and crash release, large synthetic libraries, trash/restore, frame composition, capture, video and print flows. The 2,001-session / 10,005-media fixture is a synthetic Linux profile, not a Windows startup benchmark. UVC uses synthetic inputs in automated tests. Screenshots are browser-harness captures, not WebView2 evidence. Consult `docs/UX5_AUDIT.md` and `docs/HARDWARE_TESTS.md` for earlier limits.
* CI runs #336, #338 and #343 passed frontend, Go/race, Windows build, startup/self-test, file-port/GDI print, installer upgrade/uninstall preservation and package integrity checks. Canon-enabled build/validation jobs were skipped because pull requests do not receive the Canon vault credentials. Those historical runs recorded package metadata and exercised the Inno Setup installer; current CI delivers the portable executable only. These are qualification results, not a signed or production release. Bit-for-bit reproducibility, a trusted signing identity, offline WebView2 installation, remaining driver-supplied language strings, target filesystem behavior and physical acceptance remain open. A missing file-port driver is explicitly reported UNVERIFIED by CI and must not be treated as physical print PASS.

## Runtime ownership follow-up

PR #43 fixed the post-merge UX6-1 finding that Windows `ResolveLibrary` probed Documents writability before `app.New` acquired the library lock. Resolution is read-only; startup acquires ownership before layout creation or SQLite work, and falls back only after a non-contention access or initialization failure. A held library lock remains a hard startup error. CI run #312 passed the ownership, resolution, Windows package and startup tests. This does not qualify real Windows Documents, OneDrive, read-only volume, removable drive or network-share behavior.
